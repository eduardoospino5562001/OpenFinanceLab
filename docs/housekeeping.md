### Housekeeping Items
   1. Assign issues amongst yourselves.
   2. Issues generally require a pull request (PR), and each PR requires a review.  When you're done with an issue:
      1. If you have made a PR, request that someone review it.  We should take turns reviewing each other's PRs.
      2. Move the issue to "In Review" in the Kanban board.
      3. When the review is finished:
         1. If there are changes to make, make them, if you agree with them.  If there is disagreement, discuss until you come to agreement.
         2. Move the issue to "Done" in the Kanban board.
      4. Pick another issue.
         1. Choose based on interest and capability.  If one is interesting to you that has been claimed by another, consider asking to collaborate together on it.
         2. If there are none readily available that have finished prerequisites, choose an issue and do as much work on it as you can.  Try the issue with the assumption that the prerequisites are finished already; we'll adjust accordingly afterwards.
         3. Move the issue to "In Progress" in the Kanban board if it is not there already.
   3. Note the repository is public so employers may be looking at your code and issues.  Let's assign someone to be the owner for each issue, including the collaborative issues.  Documentation of some kind (code or document) needed for every issue (check deliverable).
   4. Don't be discouraged by the size of the project.  It's large, but don't expect to do it all yourselves; others will join the project later.  It originally had fewer issues that were bigger, but was changed because small issues hopefully get done more quickly and progress is seen more easily.
   5. Issues tagged "collaborative" will require at least one reviewer outside of those who collaborated on it, unless the whole team worked on it.
   6. If you get stuck on a problem and haven't been able to figure it out after trying it for a while, please contact each other to ask questions!  We all progress when we help each other out.
